# 使用教程

从创建第一个连接开始，逐步使用终端、文件、监控和 AI 助手。教程随程序安装，无需连接外网即可阅读。

## 第一次连接服务器

1. 在左侧“分组与服务器”中新建分组，可用父分组组织不同环境。
2. 在分组下添加主机，填写名称、IP 或域名、SSH 端口（通常为 `22`）。
3. 为主机添加账户，填写用户名，并配置密码或私钥；服务器和账户均需启用。
4. 选择账户建立连接，即可使用终端与监控、文件、进程和存储管理。

分组、主机和账户支持编辑、拖拽排序与移动。删除分组或主机会级联删除其下关联配置，请先确认范围，必要时通过“数据管理”导出备份。

## 终端与多个标签

单击账户切换连接；双击账户，或在账户的更多菜单选择“新建终端”，可为同一账户重复打开独立终端。标签显示主机名称、IP 和账户，便于区分。

主机树宽度与折叠状态、监控区宽度与展开状态，以及终端和文件区的高度比例与折叠状态，会保存在当前浏览器中。使用相同地址再次打开时会恢复；协议、主机或端口变化时，浏览器会分别保存。

| 操作 | 使用方法 |
| --- | --- |
| 搜索终端文字 | 聚焦终端后按 `Ctrl+F`，在搜索栏查找输出 |
| 复制选中文字 | `Ctrl+C` 或 `Ctrl+Insert`；未选中文字时 `Ctrl+C` 发送中断 |
| 粘贴 | `Ctrl+Shift+V` 或 `Shift+Insert`，也可使用终端右键菜单 |
| 查看快捷操作 | 在终端区域单击右键；保留已选文字，可点击“复制” |
| 区分连接方式 | 查看终端顶栏右上角的 SSH / tmux 标识 |
| 滚动查看历史输出 | 在终端内使用鼠标滚轮或触控板双指上下滑动；向下滚动返回最新输出 |

普通命令行中的滚动用于查看历史命令与输出，不会切换正在输入的命令。进入 vim 等文本编辑器后，滚动交给编辑器；未开启鼠标支持的编辑器使用上下移动文本行。退出编辑器后恢复历史输出滚动。

终端中直接拖动可选择文字，双击选择词语，三击选择整行；开启 tmux 鼠标滚动后仍可直接选字，再使用复制快捷键。需要把鼠标左键点击或拖动交给 vim 等远端程序时，macOS 按住 `Command`，其他系统按住 `Ctrl` 操作。原有 macOS `Option`、其他系统 `Shift` 的强制选字方式仍可使用。

远端 Linux 安装 `tmux` 后，可使用 tmux 保留远端终端会话。普通 SSH 连接断开后无法保留现场；刷新网页可恢复当前浏览器标签页保存的终端标签，但仍需重新建立 SSH 连接。剪贴板能力受浏览器权限及访问方式影响，局域网 HTTP 地址可能需要手动选择和复制。

## 浏览文件与传输

文件区位于终端下方，可调整终端与文件区的高度比例。进入目录后，可以上传、下载、重命名或删除文件，文件夹也支持上传和下载。

“跟随终端目录”和“上传后归属终端用户”的开关状态保存在当前浏览器，刷新或重新打开后恢复，使用相同地址的其他连接也沿用该选择。只保存开关，不保存用户名或 UID/GID；上传归属仍以当前终端检测结果为准，无法确认时会阻止按旧身份上传。手动导航目录会关闭跟随并记住该状态。如果开关状态写入失败，当前会话内仍保留选择。

双击目录进入目录，双击文本文件打开只读查看；二进制文件会提示不支持文本预览，不会自动下载。编辑和下载请使用对应菜单或按钮。弹窗与“独立窗口”均支持拖选文本，按 `Ctrl+C` / `⌘C` 或点击“复制选中”复制；“复制已加载文本”只复制当前加载的内容。

查找和筛选区默认收起，点击工具栏“查找 / 筛选”或按 `Ctrl+F` / `⌘F` 展开，不会唤起浏览器搜索。一个输入框提供三种模式，默认是“查找当前内容”：高亮匹配、上下跳转，保留全部文本；“筛选当前内容”只显示已加载原文里的匹配行；“筛选整个文件”需要选择该模式后主动点击“扫描整个文件”或按 Enter，才会启动远端扫描。输入关键词、切换模式或窗口均不会自动启动全文件扫描。全文件参数改动后，旧结果会保留其已应用关键词并提示尚未重新扫描。

“筛选当前内容”完全在浏览器处理查看器保留的原文缓存，提示“仅筛选已加载内容”，使用“片段行号”而非文件绝对行号。它不会额外读取文件或启动 Tail；已经运行的普通 Tail 继续把新增原文加入缓存，再增量更新匹配结果。修改关键词会从原文缓存重新过滤，不会在旧结果上叠加筛选；缓存淘汰时对应结果一起淘汰。结果末尾、刷新和输入操作都不会隐式读取未加载历史。该模式保留当前编码，恢复原文后可更换编码。

两种筛选均支持区分大小写和前后两行上下文，重叠上下文只显示一次。“恢复原文”或退出当前筛选模式会回到原来的阅读位置。复制筛选结果只复制当前已展示的行文本，不含行号。普通查看最多保留 16 个原文块；筛选最多展示 10,000 行或约 4 Mi 个 UTF-16 字符单元（含上下文），达到上限会明确提示。任意长行都会在当前扫描范围内完整检查关键词，单行显示采用最多 65,536 个字符单元的有界片段；命中靠后时展示命中附近内容，并标记“超长行，部分内容省略”。本地筛选不会为补齐长行读取远端内容。

全文件筛选不依赖 Python。启动时探测原生 `grep`、`tail` 及读取、编码校验、进程控制所需能力，支持的组合显示“远端grep扫描”；目前原生路径用于 UTF-8、区分大小写、固定字符串匹配，要求扫描快照为空或以换行结束，末尾两行可在 64 KiB 内安全交接。未换行末行、其他编码/大小写语义、命令或执行权限、参数及进程控制能力不满足时，自动显示“SFTP兼容扫描”及原因，由 Java 完成相同筛选功能。

原生扫描对固定文件快照先校验编码和统计行数，再用 grep 扫描，只传回匹配行与上下文；后端有界解析并通过 WebSocket 推送。原生命令会自行读取文件，收到 ACK 后再接收下一批不等于远端按需读取 256 KiB：256 KiB 是后端每次接收原生输出的预算，原文/SFTP 扫描则保留每批 256 KiB 总读取预算（含校验）。暂停、待确认批次及断线会独立暂停已验证的远端进程组；取消和过期会回收进程组。原生命令达到资源限制或通道失败时，在回收进程后切换 SFTP，字节进度可能暂时回退，但已有行号、序号和结果预算不会重复计数。文件改变不会被当成普通能力回退。

全文件扫描完成后先核对快照边界、文件身份与尾部上下文，再把绝对行号和匹配状态交给 SFTP Tail；扫描期间追加的内容从快照末尾继续处理，包括未换行的新尾行。原生路径的固定前缀/边界校验与现有 SFTP 校验一样，不能证明任意中间位置未被原地改写。文件截断或检测到轮转、改写时，会保留旧内容并加上 `===================truncated===================`，重新读取后继续输出。

原文查看的“置底”或滚到真实文件末尾可以打开 Tail；本地筛选的“结果末尾”只滚动当前结果。向上阅读、搜索跳转或选中文本会暂停追踪。Tail 活跃时约 200ms 检查新增内容，连续空闲时按 400、800、1000ms 退避，新增内容后恢复 200ms；实际延迟还受调度、SSH 往返与负载影响。积压未到末尾时，每批确认后立即排队读取下一批。每个订阅只允许一个读取任务和一个未确认帧，多个订阅通过有界 FIFO 队列轮流执行；15 秒心跳和断线序号续接保留。

普通原文与全文件筛选的 Tail 复用当前 SSH 连接上的专用 SFTP 通道和文件句柄，暂停 30 秒后释放该通道，恢复时从保存位置继续。关闭查看器会取消任务并释放资源；连接中断可短暂续接，过期后回收。原文和筛选文本采用有键的增量渲染，选择或暂停期间的在途数据会暂存，恢复后只追加一次。空闲全文件筛选游标保留 10 分钟。

GBK 等多字节编码在首次接管普通 Tail 时需要确定字符边界；若此前 64 KiB 内没有换行且无法从文件开头确定边界，会明确提示切换编码或重新读取，避免产生乱码。

每个终端标签会记录最后一次成功打开的 SFTP 目录，同一账户的多个标签也各自独立。刷新后恢复标签时，会同时恢复对应目录；目录已删除或无权访问时，会提示并尝试返回默认目录。目录记录随标签保存在当前浏览器标签页的会话存储中，关闭后能否恢复取决于浏览器的会话恢复机制。

点击“传输列表”查看当前服务器下的传输任务、进度、速度及错误。切换页面不会取消本页仍在执行的任务；上传按块发送，适合大文件，仍需确保两端磁盘空间充足。

刷新或关闭浏览器会中断页面内传输，目前不支持断点续传。重新打开后，历史记录可显示最后进度，但不能自动续传；“结果待确认”需要检查远端文件。由浏览器接管的下载，请在浏览器下载列表查看实际进度与结果。

## 监控面板与自定义卡片

监控区显示 CPU、内存、网络、磁盘、inode 和可用的 GPU 等指标。卡片可拖拽排序，使用卡片上的放大按钮查看详情。

1. 在监控区切换或新增面板，按 `Ctrl+Space` 可循环切换面板。
2. 打开监控设置，调整采样间隔、暂停状态、趋势范围以及当前面板显示的卡片。
3. 在设置右侧管理自定义脚本卡片：填写名称、类型和脚本，参考界面提供的 JSON 输出框架。
4. 保存后观察卡片输出；出现脚本错误时检查命令权限、依赖及输出格式。

配置按账户保存，各面板可选择不同卡片，新卡片默认加入当前面板。每个账户最多 20 个自定义脚本卡片，支持文本、状态、数值、进度、JSON 表格、折线、柱状和饼图等类型。脚本超时不得超过采样间隔的 60%。

折线图可按时间保存连续采样；历史趋势存放在当前浏览器，按选择的 5、15 或 30 分钟范围裁剪。暂停、断开或离开页面期间不补采，速率指标可能需要连续两次有效采样。图表显示等待数据时，先检查连接、采样状态与脚本输出。

## AI 助手

点击顶栏“AI 助手”或按 `Ctrl+Shift+K` 打开。助手支持拖拽移动、调整大小和全屏，操作其他页面时可以保持打开；默认不在启动时自动弹出，可在设置中更改。

1. 打开助手的“设置 → 厂商配置”，填写 OpenAI 兼容厂商的地址、模型和 API Key。地址通常包含 `/v1`，模型需支持工具调用。
2. 选择已保存的模型及操作账户，确认授权模式。
3. 输入任务，按 `Enter` 发送，按 `Ctrl+Enter` 换行。
4. 查看流式回复和工具执行结果，点击复制按钮可复制消息或代码。

默认“全部权限”会自动执行已开放工具，包括写操作；切换为询问模式后，写操作需要确认。可以要求 AI 管理分组、主机、账户及监控面板和卡片，排查进程、执行命令、操作文件或编写脚本。任务中请说明目标账户和面板，例如：“在当前账户的巡检面板创建 CPU 时间趋势卡片”。

“历史”可恢复之前的对话，切换已连接账户会加载对应账户的最近会话。历史会话可在“数据管理 → 清除数据”中清理。附件是临时数据，过期或服务重启后需重新选择；发送的消息、附件和工具结果会交给所选 AI 厂商。

## 脚本与定时任务

在“脚本与定时任务”页面新建脚本，选择执行账户并填写 Shell 内容。先手动执行，检查输出与退出码，再设置定时规则和启用任务。执行历史可查看日志、状态及结束运行。

定时任务由 Doumi Shell 服务端独立执行：浏览器不必打开，也不要求提前建立终端连接；后台会使用保存的账户凭据建立 SSH 连接。部署程序必须持续运行，目标机器需可达。脚本不主动输出内容时，日志可能为空，请结合退出码和实际效果判断。

## 进程与存储管理

“进程”页面可按 PID、用户或命令过滤，查看完整命令，按需正常停止或强制停止进程。

“存储管理”可扫描目录占用和大文件，点击子目录继续深入，也可以定位到文件区操作。扫描大目录可能需要较长时间；先选择具体目录能缩小范围。

## 配置备份与清理

在“数据管理 → 配置导入导出”导出备份，保存分组、主机、账户、脚本及监控配置。包含凭据的备份请妥善保管，优先使用加密导出；导入后核对数量及配置。

支持从 **FinalShell** 快速迁移主机、账号与多级分组：
- 支持上传 FinalShell 导出的 `.zip` 压缩包（保留原目录与多级分组层级）或单个 `*.json` 配置文件。
- 支持直接填写本机或服务器上的 FinalShell 导出目录路径（例如 `/Users/pino/Downloads/finalshell`）直接导入。
- 可指定导入到已有分组下作为子分组，或直接保留在顶层；支持设置同名主机/账号是否覆盖更新。
- 自动识别并解密 FinalShell 3.x/4.x（MD5 随机种子 DES）及 2.x（固定密钥 DES）加密保存的 SSH 密码，并由系统主密钥安全重加密存储。

在“数据管理 → 定时远程备份”可配置将链接与运维配置按 Cron 定时自动上传至指定 MinIO (S3) 存储桶或 SFTP 服务器。支持设置周期调度、AES-256-GCM 加密密码、连通性测试及手动立即触发备份，备份凭据由本地主密钥安全加密保存。

“清除数据”可按类型和时间范围清理历史。请先预览影响范围，清理历史不会代替配置备份。需要备份整个数据目录时，先停止程序，并同时保留数据库和 `master.key`，否则已保存的凭据无法解密。

## 部署、升级与常见问题

Windows 使用 MSI 安装包；Linux x64 解压后使用 Java 17 运行 `run-linux.sh`。Linux 部署后，局域网设备可通过 `http://服务器IP:端口/` 访问，需放行对应端口。默认端口为 80，可用 `DOUMI_PORT` 修改，用 `DOUMI_DATA_DIR` 指定独立数据目录。

“关于 → 检查更新”只检测并提供下载，不会自动安装。Windows 先在托盘退出旧程序，再安装新 MSI；Linux 停止服务后替换程序并重启，保留原数据目录、密钥和启动参数。升级会中断当前连接和正在运行的任务，应先等待任务结束。

| 情况 | 检查方法 |
| --- | --- |
| 网页打不开 | 确认服务运行、地址和端口正确，检查防火墙及端口占用 |
| SSH 连接失败 | 核对目标地址、端口、账户凭据及网络连通性 |
| 没有监控数据 | 检查连接、暂停状态、卡片开关及脚本输出；速率指标等待后续采样 |
| AI 请求失败 | 检查部署机器到厂商的网络、Base URL、模型工具调用支持和密钥 |
| 更新后界面仍旧 | 确认升级的是部署机器上的程序，再刷新网页加载新资源 |
