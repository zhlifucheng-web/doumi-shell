# 文件传输流程

## 单文件上传

1. 页面选中文件后加入共享队列；捕获账户、SSH 会话和目标目录，切换页面不会改变任务目标。
2. `/upload/start` 校验文件名和总长度，创建独立任务 ID，在远程目标同目录独占创建权限为 `600` 的临时文件。原目标保持原样。
3. `/upload/chunk` 每次接收最多 8 MB，页面发送 4 MB。服务端按任务串行写入，校验顺序、已写入长度和总长度，确认远程写入后才更新进度。偏移和总长度均用 `long`。
4. `/upload/complete` 检查累计长度和远程文件长度，保留已有普通文件的权限位，再执行原子替换。页面此时显示「保存中」，等待结果，不再接受取消。
5. 出错或取消时，页面用独立请求调用 `/upload/cancel`。清理与分块共用任务锁，等待在途分块结束后删除临时文件，晚到的分块请求会被拒绝。

任务 ID 绑定原会话，不能跨会话操作。同名文件并发上传各用独立临时文件，以最后成功提交的完整文件为准。单个页面队列串行执行，不同页面可并发。空文件无需发送分块，直接提交。

不支持安全覆盖的旧 SFTP 服务端只尝试普通重命名，不通过删除原目标模拟覆盖。覆盖失败时保留原文件并清理临时文件。新文件属于当前 SSH 用户，替换也会产生新 inode，原文件的所有者、ACL、扩展属性和硬链接关系不会自动复制。

## 下载

服务端打开 SFTP 文件后直接流式输出，响应关闭时关闭远程文件和 SFTP 通道，读取期间更新会话活跃时间。大小通过 `Content-Length` 传递，不将整个文件读入内存。

- HTTPS / localhost 下支持文件保存接口的浏览器：选择本机目标后进入队列，按读取、写入顺序流式落盘，进度按已写入字节更新。失败或取消时放弃本机临时写入；结束前检查响应长度，再关闭写入流提交文件。
- 其他环境：点击后直接交给浏览器下载管理器。页面只记录「已交给浏览器」，无法观察下载结果或替浏览器取消，不显示虚假的百分比。

文件传输中的远程文件不应被外部程序修改。长度检查不是内容校验，不提供远程文件快照或哈希验证。

## 状态与列表

文件列表的属主、属组以 SFTP 返回的 UID/GID 为准，按当前目录中的不同 ID 批量调用远端 `getent passwd/group` 查询名称，支持系统配置的 LDAP 等 NSS 来源。没有 `getent` 时尝试读取远端 `/etc/passwd` 和 `/etc/group`；无法查询或 ID 无对应账户时显示数字。SFTP 服务端未提供 UID/GID 时显示“—”，不会默认显示 root。Windows 或仅允许 SFTP 的服务端若不支持 Unix 名称查询，同样保留数字或“—”，不影响文件列表使用。

页面管理的任务：等待中 → 传输中 → 保存中 → 已完成。异常转为失败；等待任务取消后立即移出队列，进行中任务进入取消中，清理返回后标为已取消。清理失败会显示提示。

清除已结束任务不会移除等待、传输、保存或取消中的任务。任务显示所属账户编号；文件和保存句柄在结束或排队取消后释放。任务列表通过“终端与监控”页面文件工具栏的“传输列表”弹窗打开，按当前服务器汇总各账户、各会话的任务，按钮显示进行中的数量；关闭弹窗不影响任务执行。清除仅作用于当前服务器。任务列表在路由切换后保留。目录请求使用序号和会话校验，旧响应不会覆盖新目录。

单文件任务的名称、账户编号、目录、状态和最后进度保存到浏览器本地存储，最多保留最近 200 条，不保存 SSH 令牌、文件内容或保存句柄。重新打开同一浏览器配置、同一协议/域名/端口时加载历史记录，刷新或重开仅恢复记录，不恢复执行，也不重新发送请求。已完成、失败、取消和浏览器接管记录保留其原状态；等待、传输和取消中的旧记录显示「无法恢复」；保存中的记录显示「结果待确认」，先检查目标文件再重试。历史百分比明确标注为最后记录进度，不能用来断言原页面任务的当前状态。其他窗口仍在运行的任务不会被本页接管或改写。

页面内传输进行中关闭或刷新会触发浏览器离开提示，但浏览器可在强制终止等情况下跳过提示；只保证显示最后成功保存的记录。存储被禁用、写入失败会显示明确提示；浏览器数据被清除、无痕窗口关闭或换访问地址后无法恢复历史。清除已结束会同步删除对应本地历史。

SSH 断线/会话过期、网络中断、保存权限被拒绝等错误附带重新发起的操作说明。原会话任务不能自动绑定新连接。提交期间发生错误时，显示「结果待确认」，避免将已提交但响应丢失的任务直接标为失败。

## 文件夹与旧接口

旧单文件上传、逐文件上传和 ZIP 还原复用临时文件加提交的写入逻辑，每个文件完整后才替换目标。整个文件夹不是事务，中断后已完成的文件和目录会保留。

直接保存文件夹逐文件流式写入，避免先构造完整文件 Blob。压缩上传仍在浏览器生成 ZIP；ZIP 下载仍使用服务端临时磁盘和浏览器 Blob，因此文件夹仍保留默认 512 MB、10000 项、64 层限制。文件夹使用独立传输对话框，尚未合并到单文件任务队列，也不保存历史进度。对话框明确说明刷新/关闭后不可恢复，传输期间注册离开提示。

## 复制到机器

文件行的「复制到」按钮或右键菜单「复制到机器…」可将当前远程文件、文件夹复制到已配置的机器及 SSH 账户。目标填写绝对目录，保留源文件或文件夹名称、完整层级和空目录；不存在的目标目录自动创建。目标仍受该账户默认目录范围限制。单次最多 10000 项、64 层，按流式处理，不使用文件夹 ZIP 传输的 512 MB 上限。

目标目录默认填入源文件面板当前所在目录，可直接修改，也可点击「选择目录」浏览接收方目录，进入子目录后选择当前目录；支持返回上级、用户主目录和根目录。接收方属主可从目标机器的用户列表选择，也可直接输入。切换接收账户会清除上一账户的属主选项；查询失败时仍可手动填写。

- **本机转发（默认）**：Doumi Shell 服务所在机器分别建立两端 SSH/SFTP 连接，在内存中使用固定大小缓冲流式中转。两端使用系统保存的账户，文件不会经过浏览器，也不会先完整落盘到部署机器。
- **直连**：源机器通过其 SSH 客户端向目标账户发送内容，文件数据不经过 Doumi Shell 服务。源机器需要 POSIX Shell、SSH 客户端、目标账户的免交互认证和已有的可信 known_hosts 记录；目标需要 Shell 和 cat。后台仍通过保存的目标账户进行路径校验、进度检查和文件提交，因此部署机器也需能连接两端。不会向源机器复制系统保存的目标密码或私钥。直连检查失败时显示原因，可重新选择本机转发。

可填写接收方用户名。后台在目标机器上解析该用户的 UID 和主组 GID，应用到复制的文件及本次新建的目录；原有目录与其他内容的归属保持原样。目录属主在其子项写入后设置，避免提前变更属主导致传输账户失去写权限。用户名解析失败会在写入前停止；内容已复制但设置属主被拒绝时，任务保留「已完成」并显示警告。留空时使用默认归属，新文件属于目标 SSH 用户，覆盖已有文件时复用现有提交逻辑保留其权限和 UID/GID。

写入前扫描整棵目录，检查同名冲突、目标类型和符号链接；不复制符号链接或设备等特殊文件。同一已识别机器上的自复制及目录复制到自身子目录会被拒绝。默认不覆盖同名文件；勾选覆盖后，每个文件先写入目标同目录的 `.doumi-copy-*.part`，长度确认完整后安全重命名提交，不删除原文件来模拟覆盖。新文件临时权限为 600；不保留源文件的执行位、ACL、扩展属性或时间戳。文件夹不是事务，失败或取消后已经提交的文件与新建目录保留，未提交的临时文件会尝试清理，清理失败会显示路径。复制期间请保持源文件稳定；长度检查不等同于快照或内容校验。

任务复用共享传输队列与当前源服务器的传输列表，展示目标机器、目标目录、进度、速度及警告，并支持取消。队列捕获源会话、源路径、目标账户、传输方式和用户名，之后切换标签或修改弹窗不会改变任务。服务端最多接收 32 个未完成任务，同时执行 2 个；状态和取消接口绑定原会话。页面每 500ms 查询状态，失去联系约 60 秒后在下一次处理检查时停止，阻塞的 SSH/SFTP 操作还受网络超时影响。刷新后仅显示历史记录，无法恢复控制或续传；关闭浏览器后应检查目标目录再重试。

接口位于 `/api/ssh-console/sftp/copy`：`POST /start` 接收 `sessionToken`、`sourcePath`、`targetAccountId`、`targetPath`、`mode`（`RELAY` / `DIRECT`）、可选 `owner` 和 `overwrite`；`GET /status`、`POST /cancel` 使用原 `sessionToken` 和任务 `id`。服务端已结束状态保留最多 1 小时、总计最多 256 条；长期历史由浏览器保存，不包含令牌或凭据。

`GET /target-users`、`GET /target-directories` 使用源 `sessionToken` 和 `targetAccountId` 查询接收方用户及目录，目录接口另接收 `path`（留空使用接收账户主目录）。每次查询独立创建临时 SSH 会话，查询结束或失败后关闭，不占用已有文件/终端会话。

## 资源与异常边界

服务端每分钟检查未结束的分块任务，30 分钟无活动后清理；写入失败的任务也会进入清理重试。最多保留 256 个未结束任务，清理持续失败一天后释放内存记录。SSH 连接断开、服务重启可能导致远程临时文件残留，可确认没有上传任务后删除 `.doumi-upload-*.part`。

不支持断点续传或自动重发分块。最后提交成功但响应丢失时，页面无法确认结果，应检查远程目标后再重试。大文件受可用磁盘、文件系统和代理超时限制，反向代理还需允许 4 MB 分块请求及长时间流式响应。
